Android Guide for Chat Vault
============================

Chat Vault is packaged as a Capacitor Android app with a static Next.js export.
The Android WebView loads the generated files from `out/`, which keeps the app
fully offline-first and compatible with the existing client-side architecture.

Audio playback on Android now prefers a native Capacitor bridge when one is present,
with HTMLAudio and WebAudio fallbacks retained for compatibility and debugging.

Project assumptions
-------------------
- App name: `ChatVault`
- App ID: `com.ayan.chatvault`
- Web directory: `out/`
- Platform: Android via Capacitor
- Android Gradle Plugin: `9.2.1`
- Gradle wrapper: `9.4.1`
- Compile/target SDK: `36`
- Min SDK: `24`

Why this approach works
-----------------------
- Chat data stays local in IndexedDB.
- ZIP parsing and media handling remain in the browser/WebView.
- Audio playback uses a native bridge when available, then falls back to HTMLAudio and WebAudio for WebView compatibility.
- Virtualized rendering with `react-window` remains client-side.
- No Next.js server actions or API routes are required.

Build flow
----------
1. Install dependencies:

```bash
npm install
```

2. Build the static web app:

```bash
npm run build
```

3. Copy the exported web assets into the Android project:

```bash
npx cap copy android
```

4. Open the native project in Android Studio:

```bash
npx cap open android
```

If you make changes to the web app, repeat steps 2 and 3.

Android project structure
-------------------------
- `android/` — native Android project generated by Capacitor.
- `android/app/src/main/assets/public/` — copied static web assets.
- `capacitor.config.ts` — Capacitor configuration for app ID, name, and web directory.

Development workflow
--------------------
- Use `npm run dev` for normal web development in the browser.
- Use `npm run build` and `npx cap copy android` before testing in Android Studio.
- Reopen the Android project if native configuration files change.

Current build notes
-------------------
- `./gradlew help` completes successfully with AGP `9.2.1` and Gradle `9.4.1`.
- The Android build currently emits deprecation warnings for several `gradle.properties` flags (`android.usesSdkInManifest.disallowed=false`, `android.enableAppCompileTimeRClass=false`, `android.builtInKotlin=false`, `android.r8.optimizedResourceShrinking=false`, and `android.defaults.buildfeatures.resvalues=true`).
- These warnings do not block the build, but they should be revisited when cleaning up the Android project for a future AGP major upgrade.
- If Android dev HMR is blocked by a Next.js origin warning, add the device host to `allowedDevOrigins` in `next.config.ts` and restart the dev server.

Android testing checklist
-------------------------
- Launch the app in an Android emulator or on a device from Android Studio.
- Verify chat import works from the file picker.
- Verify ZIP imports still parse correctly and media attachments appear.
- Verify audio playback starts, pauses, stops, switches correctly, and falls back cleanly if the native bridge is unavailable.
- Verify chat scrolling stays smooth with virtualized rendering.
- Verify media viewer and local image/video playback work in WebView.
- Verify the app still works offline after initial install.

Troubleshooting
---------------
- If the app shows old content, rerun `npm run build` and `npx cap copy android`.
- If the Android app does not reflect recent web changes, confirm `out/` was refreshed.
- If file import does not open on device, test in Android Studio and confirm the WebView file picker has access.
- If audio acts strangely, rebuild the app and clear any old cached data in the Android emulator/device.

Release notes
-------------
- Keep the app fully client-rendered.
- Do not add server actions or API routes for Android support.
- Keep new features compatible with static export and Capacitor WebView.
- If you add new native features, document them here and update `README.md` and `CONTRIBUTING.md`.
